About the compendium

A single place to check what is known about approximating NP-hard problems in FPT time: the best algorithms, the strongest lower bounds, and where the gaps are.

What belongs here

Results on parameterized approximation: algorithms that achieve an approximation ratio in time \(f(k)\cdot n^{O(1)}\) for some parameter \(k\), and lower bounds ruling such algorithms out under assumptions such as Gap-ETH, ETH, PIH or W[1] \(\neq\) FPT. Polynomial-time approximations and exact FPT results are welcome as context when they help place a problem.

Each problem shows its best known algorithm and lower bound side by side, with a status:

  • Tight: the algorithm matches the lower bound.
  • Gap remains: both are known, but they don't match.
  • No lower bound known or No algorithm known: only one side has been studied.

How submissions work

  1. Anyone can submit a result: a link to the paper, the problem, the result statements (with LaTeX) and a few tags. The form shows a live preview.
  2. The submission is recorded as a public GitHub issue, or sent by email if you don't have a GitHub account.
  3. An editor checks it against the paper. If something is unclear, the editor asks on the issue, and you're notified.
  4. Once approved, it is added to the compendium automatically and you're credited on the entry.

Spotted a mistake in an existing entry? Use Add a result on that problem and explain the correction in the note to the editors, or email fptapprox@gmail.com.

Using the data

Everything on the site comes from one file, data/compendium.json, which you are free to download and reuse. The references are also available as BibTeX. Every problem has its own link (use Copy link) for citing in talks and papers.

History

The compendium grew out of the List of FPT+Approximation results started in 2019. The original list is kept unchanged as an archive.

For editors

Open the editors' page. The first time, it walks you through creating a GitHub access token. After that:

  • Approve and publish adds the submission to the site within a couple of minutes and notifies the submitter.
  • Ask the submitter posts a question on the submission and keeps it pending.
  • Reject closes it with your explanation.
  • To fix a typo in a submission before approving, open it on GitHub, edit the JSON block, and then approve.
  • Emailed submissions: paste the email into the Add an emailed submission tab.
  • To correct or reorganise existing entries (for example, to mark a problem as tight), use the Edit existing entries tab.

To add another editor, add their GitHub account as a collaborator on the repository (Settings → Collaborators).
